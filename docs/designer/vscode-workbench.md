# VS Code designer workbench

## Market review

The November 2026 review covers desktop XAML designers, declarative-code previews, runtime inspectors, and canvas-first component tools. Design-time previews show literals and layout from an authored view. Runtime inspectors can display values that depend on a running app, which changes what their Properties views can promise.

## Decisions for FerroUI

- **Dock the tools in the workbench.** Toolbox, Outline, and Properties are separate VS Code `WebviewView`s. They share the FerroUI sidebar by default, and users can hide, reorder, and move each through VS Code’s layout commands. Outline has keyboard navigation and explicit before, after, and inside drop zones. The shared pointer gesture spans canvases and docks without invoking the workbench’s file drag overlay. [VS Code view guidance](https://code.visualstudio.com/api/ux-guidelines/views) · [Custom layout](https://code.visualstudio.com/docs/configure/custom-layout) · [Workbench drop behavior](https://github.com/microsoft/vscode/issues/182449)
- **Keep the canvas compact.** One toolbar holds source modes, viewport options, zoom, and quick access to the three docked views. Viewport size and theme live in a popover. Fit uses the available editor space, manual zoom keeps the point of interest in place, and Space-drag pans the viewport. A ready frame needs no status row. Loading, render errors, and partial previews have concise feedback.
- **Follow authored selection everywhere.** The active designer or its active source editor supplies both views. Click a control in the canvas or Outline to select it and reveal it in an already visible source editor. Double-click the canvas control or use the reveal action to open the source explicitly. Each property action carries a session, frame token, and node identity, and the source version is checked before applying the edit.
- **Separate render settings from navigation.** Logical viewport size and theme change native layout. Zoom and pan are local presentation operations, so they stay responsive during source edits and reuse the current pixels. A stale frame remains visible while syntax is repaired. The editable inspector resumes when a matching source snapshot is ready.
- **Give runtime updates their own lifecycle.** A saved revision may apply in place, be rejected by the runtime, or trigger a rebuild. Report each result in the workbench. Retain the running app until a replacement process acknowledges startup. Uno surfaces runtime connection status and per-change diagnostics, and Flutter exposes separate reload, restart, and rebuild paths. [Uno hot reload](https://platform.uno/docs/articles/features/working-with-xaml-hot-reload.html) · [Flutter hot reload](https://docs.flutter.dev/tools/hot-reload)
