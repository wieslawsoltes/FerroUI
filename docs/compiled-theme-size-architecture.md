# Where the editable WinUI executable spends its bytes

The reference executable is the 28,324,712-byte stripped Linux x86-64 PIE at runtime revision `ff5ea13a`, built with whole-graph profile use, `opt-level=z`, FatLTO, safe ICF and packed relative relocations. The next 30% target is **19,827,298 bytes**. Reaching it requires removing **8,497,414 bytes from this executable**. Both numbers refer to the installed ELF containing all 169 WinUI documents and the editable runtime. [Reference measurements and rebuild instructions](compiled-theme-performance.md#whole-graph-profile-guided-release)

| File-backed bytes | Baseline |
|---|---:|
| Machine instructions in `.text` | 18,592,421 |
| Unwind frame records, search index and exception tables | 6,060,176 |
| `.rodata` including the embedded FXP | 1,722,967 |
| Relocated read-only data in `.data.rel.ro` | 1,711,288 |
| Other sections, headers and file alignment | 237,860 |
| **Complete file** | **28,324,712** |

The 296,347-byte FXP occurs once. Even eliminating every byte of that archive would cover only 3.5% of the required saving. The dynamic linker uses 27,240 bytes of RELR for 111,346 relative relocations. The larger cost is what the referenced tables make reachable. In `.data.rel.ro` alone, 85,769 pointer slots point to 42,613 distinct instruction addresses. Several pointers can refer to the same implementation. A method referenced by both a virtual table and a descriptor still occupies a single physical range.

## Results from the implementation trials

| Full release with the same profile data and link policy | Stripped bytes | Smaller than previous best | Boxed style notification and read |
|---|---:|---:|---|
| **Retained release** | **28,324,712** | — | Reference |
| Shared observable and target lifecycle | 27,534,728 | 789,984 B (2.79%) | 39.8% slower |
| Typed notification with shared installation and allocation-identity comparison | 27,751,768 | 572,944 B (2.02%) | 36.7% slower |
| Isolated cold required-type lookup | 28,187,888 | **136,824 B (0.48%)** | Byte-identical Base library and inputs |

The grouped-lookup experiment leaves **8,360,590 bytes** to the budget. Its full-interpreter timing prevented promotion. Rebuilding the retained runtime reproduced the complete 28,324,712-byte reference, SHA-256 `459ea34851eb89e3556a9539da29b3bcbc7fa5a8af34ee2c2291f393dae85f21`. This rebuilt executable passed all eight archive checks. Machine code shrank by 123,216 bytes, exception tables by 10,116 bytes, and frame records and their search index by 2,704 bytes. The equivalent Base fixture passed all 338 property and binding cases. All 36 class registration and virtual dispatch cases, 108 XamlX cases and eight embedded/external archive checks passed. All 894 FXB blocks and the complete editable archive are byte-identical. Of 899 generated files, only the module declaration containing the absolute build directory needed path normalization for comparison.

The first 81-launch comparison reached the typed Button resource in 9.61 ms median versus 9.80 ms for the reference. An independent 121-pair repeat gave 9.07 versus 8.95 ms (paired 95% ratio interval 0.992–1.033). Scalar and structural edits were also consistent with parity in the repeat. The complete interpreter fallback took **1.701 s vs 1.585 s** over 19 fresh process pairs pinned to CPU 7. Its median paired ratio was **1.068** (95% interval **1.023–1.110**). A separate eight-pair check on CPU 6 yielded a thread-CPU ratio of 0.990 (interval 0.929–1.132). These are independent cohorts, not a pooled comparison.

Six additional pairs sampled the main-thread stacks during the full fallback. About 86% contained AST transformation frames on each build. Of 2,499 samples on the candidate, none contained the grouped-lookup helper and two contained an affected required-type constructor. The data locate the expensive workload. They leave the causal breakdown of its timing difference unresolved. The debug hot-reload test preserved subscription identity, rollback and subsequent two-way write-back. A headless companion linked from the exact candidate libraries activated Button, ScrollViewer, NavigationView and a held-out Slider using embedded, scalar-edited and structurally edited archives. Each case produced one visual root and the expected subtree of 2, 8, 26 and 2 nodes respectively, including the control. The companion used ThinLTO for correctness and did not measure painted frames. The new-lookup tests and executable are pinned to [the isolated XAML trial](https://github.com/wieslawsoltes/FerroUI/commit/1de0d6e61f98c548c4a6b8c5a1b77b93aff3c884).

A traversal prototype retained each visited node so it could borrow its lexical scope on demand. Across 967,528 visits in the real 169-file WinUI corpus, it took 8.0% longer (paired 95% interval 1.8–14.1%). A second version cached one immutable scope and passed 108 XamlX cases. Its ratio was 1.018 (0.898–1.130) and its stripped traversal fixture grew from 608,792 to 610,240 bytes. Both remained experiments.

The shared-observer and typed-delivery implementations can be inspected at their measured revisions. All three experiments remain recorded in the PR history. None changes the selected default runtime. ## Attribution after final linking

The symbolized twin matches the shipping addresses, sizes and SHA-256 digests of seven sections, including `.text`, the unwind tables and relocated read-only data. The 87,388 linked symbol records cover 80,615 physical code ranges. The table assigns each range once. Its last column includes associated frame records, their search-index entries and exception-table spans.

| Linked owner | Machine code | Code and unwind data |
|---|---:|---:|
| Dependency-property registration, stores and observers | 4,667,708 B | 6,148,696 B |
| Other framework and application functions | 3,531,594 B | 4,464,906 B |
| Callable entries and trait shims | 2,063,465 B | 2,976,001 B |
| Generated native XAML | 1,920,135 B | 2,473,911 B |
| Other XAML runtime and codecs | 1,513,721 B | 1,856,245 B |
| Bindings, reactive operators and events | 1,035,599 B | 1,344,695 B |
| Reflection and conversion | 876,159 B | 1,257,035 B |
| Compiler-generated destruction | 703,070 B | 1,039,650 B |
| Remaining categories, aliases and padding | 2,280,970 B | 3,091,458 B |

Replaying the exact final object with identical-code folding disabled increased the executable to 29,726,424 bytes. Safe ICF already saves 1,401,712 bytes here. Switching from safe ICF to `--icf=all` produced the very same 28,324,712-byte file and SHA-256 digest.

* **Repeated instructions often use different operands.** For 18,584,943 bytes that matched the final relocatable object, masking only relocation operands found 4,872 repeated instruction patterns. Keeping one body per pattern would remove at most 5,649,957 matched instruction bytes before paying for adapters. Associated frame records and index entries beyond one frame per group occupy 2,570,428 bytes. Their sum is 8,220,385 bytes, still 277,029 bytes short of the target before accounting for the new representation. This limit applies only to keeping one existing normalized body and its frame per exact-shape group. Redesigning differently shaped functions, partial sequences, exception actions or data can change the result. A hypothetical table with one eight-byte entry per varying operand of each distinct vector would consume 1,031,632 bytes. That scenario leaves 1,308,661 bytes still to find, even before paying for dispatch. A local dictionary or 32-bit relative index changes this arithmetic and must be measured on the linked file. Only 168,940 excess instruction bytes also have identical resolved operand vectors. Some function addresses are observable.
* **Property specialization is the first place to share policy.** The 260 `StyledProperty<T>::route_bind` implementations alone occupy 343,228 instruction bytes. One group contains 62 bodies of 1,355 bytes each, differing at only five of 58 relocation sites. Giving each of those 62 cases five independent 64-bit operands would use 2,480 table bytes. Sharing the policy with the existing typed operations must still pay for calling them. Another group contains 74 boxed `IObserver::on_next` bodies of 933 bytes each, differing at six sites. Across the matched property category, repeated instruction patterns account for 2,748,363 bytes beyond one body per pattern.
* **A profile covers a workload.** The profile recorded execution for at least one alias of 3,483,864 instruction bytes and zero executions for every matched alias of 14,457,313 bytes. External documents, custom controls, error paths and cleanup can reach code outside these training cases. These cold paths are candidates for a compact representation. Their required behavior remains part of the byte and performance gates.

## What XAML retains

In the same executable, 201 visual-tree factories occupy 997,726 instruction bytes, 206 style and theme factories occupy 644,736 bytes, and dictionary installation occupies 200,811 bytes. The 351 small operand functions total 17,551 bytes. All 894 stable FXB identifiers together account for 63,382 bytes. The 874 markup type headers consume 307,648 bytes, with another 196,576 bytes in eight kinds of member tables. Those descriptors directly reference 872,430 bytes of distinct invocation and typed adapter code. The descriptor view overlaps the physical ranges in the owner table above.

An experimental instruction stream replayed 1,177 real generated setter operations. Two-byte instructions cut object-file machine code by 37,941 bytes and frame data by 6,552 bytes. Static data rose by 35,304 bytes because repeated property getter references occupied separate import slots. Total allocated object sections fell by 7,809 bytes. Linked as isolated shared libraries, the direct fixture measured 206,216 bytes, the indexed version 197,032 bytes, and the version with a function per distinct operation 210,272 bytes. The release uses the existing setter path. These fixtures measure representation costs rather than a whole-application saving.

## Choosing where Rust specializes

The API requires type-specific reads, writes, coercion, comparison, binding callbacks and boxing with the correct Rust `Any` identity. Experiments can isolate the policy around those operations from the typed leaves. Rust instantiates reachable generic code for each concrete type. Moving a common policy into a non-generic function removes that duplication at its source. Dynamic dispatch introduces an indirect call and can restrict inlining, so its position in the call path matters. [rustc monomorphization](https://rustc-dev-guide.rust-lang.org/backend/monomorph.html) · [Rust trait objects](https://doc.rust-lang.org/reference/types/trait-object.html)

| Path examined | Candidate shared protocol | Operations kept typed in the experiments |
|---|---|---|
| Boxed observable → styled or direct property | Select and install a non-local styled binding frame. Replace the local subscription for direct and local styled bindings | Deliver updates with the original typed observer, validate for `T`, cache `Option<T>` and return `T` to a typed reader |
| Compiled binding from a plain data-context property | Validate attachment, log failures and complete the sink/frame after unsubscribe | Subscribe, guard against reentrant write-back, publish, read or write the source, and keep its typed cached value |
| XamlX required-type lookup | Resolve consecutive required types in declaration order using one shared traversal | Keep the array size and result positions fixed in the caller |
| XamlX member lookup | An experimental traversal accepted a borrowed predicate | The isolated trial retained the original specialized hierarchy traversal |

The first refactor also redirected per-notification work through an erased observer. All 338 enabled integration tests passed, but styled boxed emission followed by a typed read took 39.8% longer versus the previous best (paired 95% interval 37.1–42.5%). Two-way compiled write-back took 5.8% longer. A second trial restored the typed observer and the compiled expression's original cached value, weak owner and reentrancy guard. It matched every reference allocation count and size, but boxed style delivery still took 36.7% longer in its own reference comparison. Disassembling the measured observer showed that the restored handler had the same 67 normalized instructions as the reference. A downstream publication call targeted a 1,475-byte body in the trial and a 14,380-byte body in the reference. The source change altered downstream code generation. The timings measure their combined effect. The isolated XAML trial changes only batched required-type lookup. A thin `get_types<const N>` wrapper supplies fixed stack storage to one `fill_type_group` loop, short-circuits on the first failure, and releases partially initialized handles in reverse lookup order. The Base runtime source and the specialized XAML member-search code match the reference. ## What would have to change for 30%

With the other file sections fixed, machine code and unwind data would need to fall from **24,652,597 to 16,155,183 bytes**, a reduction of **34.47%**. If unwind data held steady, `.text` alone would have to shrink **45.70%**. A size budget for a subsystem must charge its descriptors, imports, alignment and remaining typed operations to the replacement, as well as any frame and exception data that disappear with its old code.

The property, callable, native XAML, XAML runtime, binding and reflection rows together occupy 16,056,583 bytes of code and unwind data. If all other sections stay fixed, those six rows must shrink by 52.9% in aggregate to reach the target, including the cost of their replacement data. The following changes are candidates for that budget. The experiments above establish where the simple versions lose size or throughput.

1. **Represent dependency-property operations once per storage shape.** Keep `StyledProperty<T>` and its ordinary typed read as the public facade. Place precedence selection, observer subscription state, raising order and frame traversal in shared code. At declaration time generate the narrow typed operations required to compare values, run validation/coercion and transfer them to or from typed storage. A prototype tested one possible specialization on fieldless enums using an explicit generated codec. Decode by matching declared variants and keep type-specific hooks for customized equality and coercion. Open user-defined types retain the general typed implementation. A state transition can return a small action enum to the typed caller, which performs the value operation directly. Re-read base priority after invoking coercion, equality, notification or a destructor: those calls may reenter the store. An isolated kernel for 110 real enum declarations and 778 variants made the 364,104-byte typed fixture 3,608 bytes larger with a 32-bit ordinal and made reads 2.28 times as expensive. Caching the typed effective value recovered read performance but still added 2,184 bytes. Keep the typed effective-value cache for hot reads and target shared cold operations. Compare default, local, inherited and coerced reads, style binding delivery, reentrant disposal and allocation counts before adopting another representation. For boxed `i32` style delivery, the 12,905-byte difference between the reference and second trial’s publication bodies is a local code-generation observation. The net cost of restoring inlining also depends on which outlined helpers survive. Compare inline decisions and call targets under representative profiles, with additional types held out. Paying that cost on a demonstrated hot route can be cheaper than replicating it for all 260 property value types.
2. **Compile templates into resolved operations with a local import dictionary.** Use compact instruction operands for constructors, property setters, resources, namescope slots and child attachment. Resolve property handles once per factory or document. Reuse one dictionary entry when several setters call the same Rust getter. Track temporary lifetimes, deferred resource identity, source spans and error order explicitly. Keep generated native calls for hot shapes until the same real control templates activate at equal or better cost. Keep imports local so an explicitly rooted theme can still drop unrelated constructors. An external structural edit must continue to reach the full registered language.
3. **Make open-world metadata cheaper per member.** Class-specific native virtual handlers that execute custom control behavior still require an implementation. Separate those from forwarding entries and reflection adapter policy. Give sealed built-in members per-module indices and share descriptor operations for common signatures. Keep a separate dynamic registration route keyed by Rust `TypeId` for user types. Generate small member-specific leaves for ownership, null handling, argument conversion, invocation and result boxing. Restrict the index to metadata resolution so ordinary typed property reads do not pay a new lookup cost. A member reachable through a dynamically edited XAML document stays discoverable. Aliased function addresses, inherited slots and executable bodies referenced by several tables must be counted only once. Measure the newly generated descriptor bytes and the in-process CPU cost of indirect calls before expanding to more types.

4. **Use one animation timeline for every value type.** Inside the 4,464,906-byte general-framework row, animation step observers, disposal observers, subscription and interpolation appear in 27 specializations each. Those four families together occupy 231,333 instruction bytes. Extract clock direction, iteration/delay arithmetic and fill decisions into a non-generic timeline that returns a small Rust enum describing the next action. Keep interpolation and publishing `A::Value` in the statically typed caller. This can share control flow without a virtual call per animated value. Verify reverse/alternate playback, infinite iterations, pause, clock stop, completion reentrancy and preview fill. The 231,333 bytes include indispensable interpolation and publication code. [Animation instance](../src/FerroUI.Base/animation/animation_instance.rs)

The exact baseline contains 779,526 instruction bytes across 111 fieldless enum payload types in the four measured property families. The corresponding counts are 306,731 for 26 strong object handle types and 50,428 for four element-reference types. Those bytes include the typed operations a replacement still needs. [Payload census and ordinal experiments](benchmarks/compiled-theme-property-shapes-linux-x86_64.json)

The strong handle also illustrates the cost of moving work from one path to another. Storing the `Rc::into_raw` data pointer directly kept two words and accelerated the isolated typed dereference loop by about 31%. It more than doubled clone/read/drop time, so the runtime keeps its existing owner representation. The second trial also used `Rc::ptr_eq` and `Weak::ptr_eq`. They compare allocation identities directly and preserve the existing hash contract. A separate 96-owner fixture saved 5,792 bytes. The isolated XAML trial kept the original owner methods so that its framework input can be checked directly against the previous best. [Carrier and ownership measurements](benchmarks/compiled-theme-handle-carrier-linux-x86_64.json) · [Allocation identity and same-image negative control](benchmarks/compiled-theme-metadata-and-replay-linux-x86_64.json) · [Rust allocation identity](https://doc.rust-lang.org/std/rc/struct.Rc.html#method.ptr_eq)

These experiments establish no verified path to the complete 8.50 MB saving. The byte gate applies to the complete current-best release policy. Compare each change individually when attribution is ambiguous, then rebuild the combined result. Keep both unchanged input profiles and per-revision retraining distinct in reports. Compare fresh-process startup, first real template activation, external edits, typed and boxed notifications, and panic cleanup. At the baseline the input object contained 27,655 exception-table sections spanning 1,668,660 bytes, with only 12,359 unique byte/relocation combinations. The linked file references 12,361 exception-table addresses. The continuing opportunity is reducing the number and complexity of cleanup paths, which shrink when duplicated binding state machines disappear. The release retains panic unwinding and a RELR-capable loader.
