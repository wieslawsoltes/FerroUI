# WinUI theme port: deviations from WinUI 3

Every place where the WinUI theme of FerroUI (`src/FerroUI.Themes.WinUI`) differs from the
WinUI 3 source it is ported from (microsoft-ui-xaml, commit
`7e4b0c2096be402f51cc8f7d203ebf67cff183d0`), one entry each: the source file and the key or
element, what WinUI does, what the port does, and why. The design is in
[../winui-theme.md](../winui-theme.md); the state of every control is in
[PROGRESS.md](PROGRESS.md) and the item-by-item tracking in [TRACKING.md](TRACKING.md).

Rules for the batches (docs/porting/winui-theme.md, section 7): every batch adds the deviations
of the controls it ports here, in a section `## <FerroUI control>` (the name of its document
under `Controls/`), one table row per deviation with an identifier in the first column
(`| BTN-1 |`), and regenerates the tracking (`scripts/winui-theme/status.py`, which counts the
rows of each section) in the same commit. A general rule that applies to many controls is written
once under "General" and not repeated per control; a control section lists what is particular to
it. Abbreviations: CS = `controls/dev/CommonStyles/`, GX = `dxaml/xcp/dxaml/themes/generic.xaml`.

## General

| ID | WinUI source | What WinUI does | What the port does | Why |
|---|---|---|---|---|
| G-1 | `VisualStateManager.VisualStateGroups` of every template | One current state per group, chosen by the code of the control; its storyboard sets values for as long as it is current. | Each state is a nested style of the control theme on the pseudo-classes of the state (`^:pointerover`, `^:checked:pressed`), in the order of the source so that the last matching style is the state WinUI would choose. | FerroUI has no visual state manager; its styles select on pseudo-classes, several of which match at once (a pressed control is also under the pointer). |
| G-2 | `ObjectAnimationUsingKeyFrames` with one discrete frame at time 0, `DoubleAnimation Duration="0"`, `VisualState.Setters` | Animations that set a value at once. | Setters of the nested style. | Same effect without an animation. |
| G-3 | `DoubleAnimation`/`SplineDoubleKeyFrame` to a value over a duration, `BeginTime` | The value is animated when the state is entered; leaving the state ends the animation and restores the base value at once; `BeginTime` delays it. | A setter of the value and a transition of the property on the element, with the duration and the spline of the source; the return to the base value animates too; begin times are not reproduced. | FerroUI animates property changes with transitions; a transition has no begin delay and runs both ways. |
| G-4 | `{ThemeResource X}` | A reference re-evaluated when the theme changes. | `{DynamicResource X}`; in a theme dictionary it resolves in the variant of that dictionary. | The counterpart in FerroUI. |
| G-5 | Theme dictionaries `Default`, `Dark`, `Light`, `HighContrast` | `Dark` is merged into `Default`; `Default` is the dark theme and the fallback; `HighContrast` is selected by the contrast setting of Windows. | `Default` and `Light` keep their keys; `HighContrast` is keyed by `WinUITheme.HighContrast`, a theme variant that inherits `Dark`, which an application requests; it is not selected from the contrast setting of the system. | FerroUI has only the light and dark variants and parses no other variant from text; the actual variant of a top level follows only light or dark of the platform. |
| G-6 | `SystemColor*Color` (named by the `HighContrast` dictionaries) | Colours of the system, from the active contrast theme. | Fixed values in `Resources/SystemResources.xaml`: the standard colours of Windows in `Default`/`Light`, the colours of "High Contrast Black" in `HighContrast`. | FerroUI has no system colours. |
| G-7 | `SystemAccentColor`, `SystemAccentColorDark1..3`, `SystemAccentColorLight1..3` | Colours of the system (`UISettings`, `SystemThemingInterop::GetSystemVariantAccentColor`). | `Accents/SystemAccentColors`: the accent of the platform settings (default `#0078D7`) and its shades as the platform reports them (`PlatformColorValues::accent_shades`, which the Windows backend reads from `UISettings` as WinUI does); where the platform reports none (macOS, Linux, the browser, mobile, no platform settings), shades computed with the lightness steps of the Fluent theme. | Only Windows has the shades of the system; elsewhere the computed shades differ from the ones Windows would compute for the same accent (`#00589B` against `#0067C0` for Dark1 of the default blue). |
| G-8 | `XamlAutoFontFamily` (GX `ContentControlThemeFontFamily`, the text styles) | Resolves to Segoe UI Variable with the optical size of the text. | `Segoe UI Variable Text, Segoe UI, $Default`. | The name is a WinUI convention; the list gives the same font on Windows 11 and the default font where Segoe is absent. FerroUI's text sets no axis of a variable font, so the optical size is the one of the named instance (Text) at every size: measured at 200 % on the text calibration page, a line of 30 characters is 4.5 px narrower than WinUI's at 12 px, the same at 14 px and 1 to 2.5 px wider from 15 px on, which moves the ends of longer texts and the labels that follow a text (the command bar buttons, the columns of the time picker) by a pixel or two. |
| G-9 | `FontIcon`, `FontIconSource`, `TextBlock` in `SymbolThemeFontFamily` | Glyphs of the Segoe Fluent Icons font. | `Path` (or `PathIcon`) of the geometry `GlyphGeometry<code point>` of `Resources/Glyphs.xaml`, sized to the ink of the glyph at the font size of the source. | The font is part of Windows, not redistributable and absent on other platforms; the outlines and their sizes are approximations to be calibrated against native WinUI. |
| G-10 | `AnimatedIcon` with an animated visual source (Lottie) | Animated glyphs whose state follows `AnimatedIcon.State`. | The fallback glyph as a static path; the states become its opacity; the `AnimatedIcon.State` setters are left out. | FerroUI has no `AnimatedIcon` and no Lottie player. |
| G-11 | `controls/dev/Materials/Reveal/RevealBrush_themeresources.xaml`, the `*RevealStyle` styles | Reveal brushes and styles, deprecated in WinUI 3 (plain fallbacks). | Waived, except the seven Reveal brushes other documents still name, ported as the plain brushes they are. | FerroUI has no Reveal lighting; the default styles are ported. |
| G-12 | `AcrylicBrush` resources (`controls/dev/Materials/Acrylic/AcrylicBrush_themeresources.xaml`, CS `Deprecated_themeresources_any.xaml`) | A blurred, tinted backdrop brush, with `FallbackColor` where acrylic is not available. | A `SolidColorBrush` of `FallbackColor` (of the tint with its opacity where there is no fallback). | FerroUI has no acrylic brush (its acrylic is a material of a border, not a brush). |
| G-13 | `DesktopAcrylicBackdrop` (`AcrylicBackgroundFillColorDefaultBackdrop`, `MenuFlyoutSystemBackdrop`), Mica of windows | System backdrops of windows and popups. | Waived; windows draw `SolidBackgroundFillColorBaseBrush`, the colour Mica falls back to. | Backdrops are a platform feature an application chooses (the transparency level of a top level). |
| G-14 | `UseSystemFocusVisuals`, `FocusVisualMargin`, `FocusVisualPrimaryBrush/Thickness`, `FocusVisualSecondaryBrush/Thickness` | The framework draws a 2 px outer and a 1 px inner rectangle around the focused element, at its margin, with its corner radius widened by the margin. | The default focus adorner of `AdornerLayer` draws the two rectangles; a control theme with a `FocusVisualMargin` sets its own `FocusAdorner` with that margin; the corner radius is `ControlCornerRadius`, not widened. `UseSystemFocusVisuals="False"` is `FocusAdorner="{x:Null}"`. | FerroUI draws focus visuals as adorners; the adorner template cannot read the corner radius of the adorned control. |
| G-15 | Keyed styles without `BasedOn` (`AccentButtonStyle`) | Applied over the default style of the control, whose setters they do not override stay in effect. | Keyed control themes are based on the default theme of their type (`BasedOn="{StaticResource DefaultButtonStyle}"`). | A FerroUI control theme replaces the default one; the base keeps the layering of WinUI. |
| G-16 | `Style="{StaticResource X}"` in an application | Sets an explicit style. | `Theme="{StaticResource X}"`; the keys are the keys of WinUI. | Control themes are FerroUI's styles of controls. |
| G-17 | `Grid`/`StackPanel` with `BorderBrush`, `BorderThickness`, `CornerRadius`, `Padding` | Panels of WinUI draw borders. | A `Border` of the same name around the panel; state setters target the border. | FerroUI panels have a background only. |
| G-18 | Template-local resources (`Grid.Resources` with `ControlTemplate x:Key`, `Style x:Name`) | Templates and styles that only the template uses. | Keyed control themes of the control document, named `<Control><Name>`. | FerroUI's templates have no local resources of control templates; a keyed theme is the counterpart. |
| G-19 | `AutomationProperties.AccessibilityView`, `ContentTransitions`, `IsTextScaleFactorEnabled`, `Control.IsTemplateFocusTarget`, `x:DeferLoadStrategy`, `x:Load`, `LineStackingStrategy`, `OpticalMarginAlignment`, `ScrollViewer` modes (`HorizontalScrollMode`, `VerticalScrollMode`, `IsHorizontalRailEnabled`, `IsVerticalRailEnabled`, `ZoomMode`) | Properties of WinUI elements. | Left out. | FerroUI has no such properties (its automation tree and text layout are its own). `TextLineBounds` is no longer among them: FerroUI's `TextBlock.TextLineBounds` (an addition, docs/porting/DEVIATIONS.md, Text block) takes WinUI's values, and the styles set it as WinUI's do. |
| G-20 | `RecognizesAccessKey` (not in the source) | WinUI's access keys (`AccessKey`) need nothing in templates. | The content presenters of buttons, toggles, check boxes and radio buttons set `RecognizesAccessKey="True"`. | FerroUI's access keys (`_File`) are recognised by the content presenter. |
| G-21 | Durations and key splines as `x:String` resources (`ControlNormalAnimationDuration`, `ControlFastOutSlowInKeySpline`) | Converted where they are used. | Kept as resources; the transitions write the values and name the resource in a comment. | A string resource cannot feed the `TimeSpan` of a transition in FerroUI. |
| G-22 | Theme animations and transitions (`FadeInThemeAnimation`, `PopupThemeTransition`, `*ThemeTransition`) | Animations defined by the framework. | Opacity and transform transitions or keyframe animations with the timing of the WinUI animation (none in the foundation; each batch records its choice). | FerroUI has no theme animations. |
| G-23 | The controls of the merged theme FerroUI has no control for (InkToolbar, MediaTransportControls, Pivot, RatingControl, PersonPicture, MapControl, TeachingTip, TwoPaneView, SwipeControl, AnnotatedScrollBar, ItemsView, ItemContainer, BreadcrumbBar, PagerControl, RadioButtons, ProgressRing, ImageIcon, ScrollView, CommandBarFlyout, RichEditBox, GridView, ListView, Hub, SemanticZoom, ContentDialog's own control, NavigationView, InfoBadge) | Styles and resources of those controls. | Their documents are waived (`scripts/winui-theme/waivers.json`, with reasons); NavigationView, InfoBar, ContentDialog, TitleBar and SelectorBar keep their resources for the FerroUI controls built from them. | No FerroUI control would use them. |
| G-24 | `ThemeShadow` with the `Translation.Z` of `ApplyElevationEffect` (`dxaml/xcp/dxaml/lib/ElevationHelper.cpp`: 32 for flyouts, menu flyouts, the drop-downs of ComboBox and AutoSuggestBox, the date and time picker flyouts and CalendarDatePicker's flyout, 8 more per submenu level, 16 for tool tips), drawn as drop shadows by the recipe of `dxaml/xcp/components/graphics/inc/DropShadowRecipe.h`; a windowed popup grows by the insets of the shadow | A soft shadow under every popup, darker in the dark theme, outside the bounds of the element. | The `BoxShadow` of the outer border of the popup content (`Resources/ThemeShadows.xaml`, written by hand from the recipe: `ThemeShadowFlyoutBoxShadow` `0 8 16 0` with the opacity 0.14 in light and 0.26 in dark, `ThemeShadowSubMenuBoxShadow` with the ambient and the directional shadow of `Translation.Z` 40, `ThemeShadowToolTipBoxShadow` `0 4 8 0`), and a margin of the insets of the recipe on the child of the popup (`ThemeShadowFlyoutMargin` 16,8,16,24, `ThemeShadowSubMenuMargin`, `ThemeShadowToolTipMargin`), which FerroUI's popup positioner leaves out of the placement (`PopupPositionerParameters.deflate`), so the shadow has room inside the popup without moving the element. The high contrast variant has the dark values. Where the element has a background sized to the inner edge of its border (`BackgroundSizing="InnerBorderEdge"`: the flyout and menu presenters, the context menu, the menu bar and submenu popups, the drop-down of ComboBox, the tool tip), the shadow is the `BoxShadow` of a border of its own around it, `ThemeShadowWrapper`, without a background or a border, with the corner radius of the element: FerroUI's border (`BorderRenderHelper`, as upstream's) draws its box shadows only when it draws itself as a rounded rectangle (a uniform border thickness, a corner radius the backend can draw, `CenterBorder` sizing) and draws none when it draws itself as geometries. The control themes of the presenters whose template draws the shadow (`MenuFlyoutPresenter`, `ContextMenu`, `FlyoutPresenter`, `ToolTip`, `DatePickerPresenter`, `TimePickerPresenter`) set `ClipToBounds` to false: a templated control of FerroUI clips to its bounds by default (as upstream's), which clipped the shadow away in a popup and in a page alike (measured at 200 %: no shadow under the menus and the flyout of the gallery, where WinUI draws one), while WinUI's controls do not clip. A presenter shown outside a popup (in a page) keeps its margin, so a page that shows one sets `Margin="0"` (the gallery does); its shadow is drawn outside its bounds, as WinUI draws the shadow of a presenter in a page. The transparent margin of a popup window takes the clicks over it. | FerroUI has no `ThemeShadow`; a `BoxShadow` is drawn outside the bounds of its border but is clipped by the popup window, which is the size of its content. The blur of a composition drop shadow and of FerroUI's box shadow are the same radius (a Gaussian of about a third of it); the shadow of a deeper submenu (`Translation.Z` 48 and more) is the one of depth 1. |
| G-25 | `BackgroundSizing` of `Border`, `Grid`, `StackPanel`, `ContentPresenter` and `Control` (`dxaml/xcp/core/core/elements/border.cpp`: the background extends under the border only for `OuterBorderEdge`) | The default is `InnerBorderEdge`: an element that draws a background and a border draws its background inside the border, so a translucent border (the stroke brushes of the palette, `CardStrokeColorDefault`, `ControlStrokeColorDefault`) is drawn over what is behind the element; WinUI has no sizing to the centre of the border. | Every element of the templates that draws a background and a border without a sizing of the source sets `BackgroundSizing="InnerBorderEdge"`; where the source sets one, it is ported. Not set: the borders that carry a `BoxShadow` (the presenters of the date and time picker flyouts, `Background`; the suggestions of AutoCompleteBox, `SuggestionsContainer`), which FerroUI draws with their shadow only as rounded rectangles of the centre sizing (G-24); the frame of WindowDrawnDecorations (no WinUI element). | FerroUI's default is `CenterBorder` (the background reaches the middle of the border, as in the reference), so the inner half of a translucent border was drawn over the background of the element: measured at 200 %, the borders of the notification cards (InfoBar) were half a pixel of the severity's colour where WinUI's are the card stroke over the page. |
| G-26 | The text of `TextBox` and `PasswordBox` (RichEdit, `dxaml/xcp/core/text/RichTextServices`) | RichEdit lays out and draws the text of a text box, with its own advances and lines stacked at whole pixels. | FerroUI's `TextPresenter` lays out the text of a text box as its text blocks do. | The text engine is the framework's. Measured at 200 %: the placeholder (a TextBlock in WinUI) is in place, the text of a box is narrower than WinUI's by about 1 px in 25 (6 device pixels over "Text content" at 14 px, 13 over the first line of the several-line box), and its lines are 18.62 px apart where RichEdit's are 18 (text-rendering.md, section 1). |
| G-27 | The defaults of `Control.HorizontalContentAlignment` and `VerticalContentAlignment` | `Center`, which the styles of WinUI leave unset and their templates bind (the content of a button, the placeholder of a combo box, the items of lists). The tab view and the refresh container are not among them: their content fills the control in WinUI. | The control themes whose WinUI style leaves them unset and whose template binds them set `Center` (the button family, the combo box and its items, the date picker, the drop-down, split, repeat, toggle and hyperlink buttons, the expander header, the list items, the selector bar items and the navigation buttons of the calendar and the date and time flyouts). | FerroUI's defaults are `Stretch`: without the setters the content of a stretched button sat at its left and a placeholder at the top of its box. |
| G-28 | The line of a single-line `TextBox` | Placed by the padding and the line height of Segoe UI, which together fill `TextControlThemeMinHeight`. | `VerticalContentAlignment` `Center` (the placeholder follows it); a box with `AcceptsReturn` keeps its text at the top. | With the fonts of macOS and Linux the line is shorter, and the text sat above the middle of the box, most visibly in the compact density. On Windows the line fills the box and nothing moves. |
| G-29 | The label of an `AppBarButton` and an `AppBarToggleButton` beside the icon (`LabelPosition` `Right`, `CommandBarDefaultLabelPosition` `Right`) | The icon and the label sit at the top of the button, with margins measured for Segoe UI so that both read as centred in the 40 px row of the command bar. | The root keeps the compact height (48) and the content grid is centred in it, with the icon and the label centred in their row; the label has `TextLineBounds` `Tight` (its box runs from its capitals to its baseline, and it does not clip what is outside), so that its capitals are in the middle; the margins keep their horizontal parts (12 before the icon, 8 between, 12 after the label). | With the fonts of macOS and Linux the label is shorter than with Segoe UI, and it sat above the icon; centring the box of a line (ascent and descent) still left the capitals of Helvetica 1 px above the middle of the icon. |
