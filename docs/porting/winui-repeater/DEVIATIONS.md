# Repeater deviations and pinned-source corrections

All source comparisons refer to
[WinUI `7e4b0c2096be402f51cc8f7d203ebf67cff183d0`](https://github.com/microsoft/microsoft-ui-xaml/tree/7e4b0c2096be402f51cc8f7d203ebf67cff183d0/controls/dev/Repeater).
A replacement in this record is a design decision, not an exemption from the
observable behavior it is intended to preserve.

|---|---|---|---|

| WR-02 | Paired `.h`/`.cpp` and generated partial sources | Consolidate small argument types and layout/context class families in idiomatic Rust modules; split lined-flow policy and row algorithm | The exact many-to-one and one-to-many correspondence is in [SOURCES.md](SOURCES.md) |
| WR-03 | WinRT collection wrappers and `InspectingDataSource` | Extend native `ItemsSource` and `ItemsSourceView` with stable-key mapping rather than introduce a second collection framework | [Source implementation](../../../src/FerroUI.Controls/items_source_view.rs), [source tests](../../../src/FerroUI.Controls.Repeater/source_view_tests.rs) |

| WR-18 | WinUI TestUI applications and packaged images | Keep every source/asset in the inventory as a reference; provide native FerroUI demonstrations and scenario tests | [Source map](SOURCES.md); exact sample application/page parity is not inferred from control parity |

| WR-21 | Ignored null-source test expects diagnostic `ItemSource` while pinned C++ emits `ItemsSource` | Preserve the C++ runtime's `ItemsSource doesn't have a value` diagnostic in the native programmer-error rejection | [Acceptance test](../../../src/FerroUI.Controls.Repeater/acceptance_tests.rs), [pinned implementation](https://github.com/microsoft/microsoft-ui-xaml/blob/7e4b0c2096be402f51cc8f7d203ebf67cff183d0/controls/dev/Repeater/ItemsRepeater.cpp#L316); the test spelling mismatch is explicit, and COM `E_FAIL` is replaced by the native panic boundary |
| WR-22 | `ItemsSourceView::Count` caches `GetSizeCore` and refreshes it on collection change; `CanQueryElementFactory` asserts those override-call counts | Preserve the existing native live `IItemsList::count` contract; do not introduce a source-size cache or a WinRT-style override solely to reproduce its invocation counts | [Native source view](../../../src/FerroUI.Controls/items_source_view.rs), [factory scenario](../../../src/FerroUI.Controls.Repeater/items_repeater_tests.rs), [pinned count implementation](https://github.com/microsoft/microsoft-ui-xaml/blob/7e4b0c2096be402f51cc8f7d203ebf67cff183d0/controls/dev/Repeater/ItemsSourceView.cpp#L12); the scenario retains data-read counts, factory get/recycle counts and element/parent identities, while size-callback frequency is explicitly a native adaptation |
| WR-23 | Rendering-frame work is sorted and drained by the pinned `BuildTreeScheduler` | Native disposable registrations retain an independently cancellable callback slot after entering the current frame snapshot | [Scheduler](../../../src/FerroUI.Controls.Repeater/build_tree_scheduler.rs); cancelling later work from an earlier callback releases its captures and prevents stale phased binding from consuming replacement work in the same frame |
| WR-24 | Reference-counted template/selector replacement can invoke application destructors | Publish the replacement and end the `RefCell` borrow before releasing the previous implementation | [Template wrapper](../../../src/FerroUI.Controls.Repeater/item_template_wrapper.rs); destructor callbacks can inspect or replace the wrapper, and a nested replacement remains authoritative |
| WR-25 | Pinned `SelectionNode::GetAt` calls `ResolvePath` before storing a child at the requested index | Validate a model-wide structural revision across source reads, `ChildrenRequested`, and child-source initialization; preserve an existing child realized by a nested request | [Selection node](../../../src/FerroUI.Controls.Repeater/selection/selection_node.rs); same-source mutations and ancestor disposal return `SelectionError::SelectionChanged` instead of caching a child at an obsolete path |
| WR-26 | A transition provider can outlive its original template, host or removal operation | Track exact removal identities; cancel element-specific work before recycling and drain the old provider before replacement | [Transition lifecycle audit](TRANSITION-LIFECYCLE.md); cancellation restores native animation-priority values before factory reuse, preserves shared hosts and repeated public completion, and lets a reentrant provider change supersede the outer change |
| WR-27 | WinUI can snapshot a disconnected target's zero `RenderSize` before its first arrange | Capture the native target rectangle only after the target and its content-space ancestors complete layout | [Bring geometry comparison](API-SHAPES.md#native-scrolling-and-bring-targets); native alignment uses the complete arranged target, with exact offset/range assertions and an explicit difference from the pinned zero-height snapshot |
| WR-28 | The temporary made anchor is released at the next rendering boundary while a host scroll animation may continue | Keep one scoped pin lease for the target and each containing Repeater realization until completion/cancellation, independently of the layout anchor | [Scrolling lifetime](TRANSITION-LIFECYCLE.md#scrolling-operations); pin generations prevent old progress/completion from acting on a recycled control, and cancellation/detachment releases the original owners' pin contributions |
| WR-29 | Pinned `ViewManager::OnItemsSourceChanged` gates removed/reset rows on `AutoRecycleCandidate`, although a suppressing layout can already have released a pinned row | Retire affected pinned-pool rows on Remove/Replace/Reset independently of the old layout flag; transfer keyed resets into the stable-key pool without losing identity or pins | [View manager](../../../src/FerroUI.Controls.Repeater/view_manager.rs), [pinned source](https://github.com/microsoft/microsoft-ui-xaml/blob/7e4b0c2096be402f51cc8f7d203ebf67cff183d0/controls/dev/Repeater/ViewManager.cpp); pinning protects against layout recycling, not removal of the source item; the suppressed rows still owned by a layout remain that layout's responsibility |
| WR-30 | Pinned `SelectionModel::OnSelectionChanged` omits item-property notifications when `Source` becomes null | Source removal also notifies `SelectedItem` and `SelectedItems` through the existing single notification sequence | [Selection model](../../../src/FerroUI.Controls.Repeater/selection/selection_model.rs); native bindings clear the old item/count and a bound Repeater empties; ordinary source-less index selection retains its existing notification contract |
| WR-31 | Pinned item-index hooks select synchronous Windows diagnostic messages | Route selected item lifecycle/arrangement snapshots through the existing native `Logger`, with weak references and deferred sink filtering/delivery | [Diagnostics](../../../src/FerroUI.Controls.Repeater/diagnostics.rs), [sink regressions](../../../src/FerroUI.Controls.Repeater/diagnostics_tests.rs); Information-level Control/Layout messages cannot reenter borrowed layout state, realize an absent selected item or retain a disposed host; Windows runtime-profiler registration, ETW schemas, debugger transport and exact upstream trace messages are intentionally not reproduced |
| WR-32 | `VirtualizationInfo` holds the phased item weakly, because a WinRT source returns the same object on every read | Hold the phased item strongly while phasing lasts; `stop_phasing` clears it | [Virtualization info](../../../src/FerroUI.Controls.Repeater/virtualization_info.rs), [phasing regression](../../../src/FerroUI.Controls.Repeater/services_tests.rs) (`later_phases_receive_the_item_of_a_source_that_boxes_on_every_read`); a typed FerroUI list boxes a new value on every `get_at`, so phases after 0 lost their item; a recycled element does not root the source |
| WR-33 | UniformGridLayout forces minor position 0 for the anchor (`FlowLayoutAlgorithm.cpp`), justifies only realized siblings and passes the raw `MaximumRowsOrColumns` | Column-based placement of every item, justification of whole logical rows, and the items per line as the line maximum | [Flow algorithm](../../../src/FerroUI.Controls.Repeater/layouts/flow_layout_algorithm.rs), [uniform grid](../../../src/FerroUI.Controls.Repeater/layouts/uniform_grid_layout.rs); fixes the scenario of the ignored upstream test `ValidateGridPlacementAfterInsertBeforeScrolledAnchor`; items keep their columns while scrolling |
| WR-34 | `ViewManager::OnItemsSourceChanged` has no Move case (WinRT vectors report a move as Remove and Add) | FerroUI lists report Move; the realized elements keep their identity, their indices are remapped and `ElementIndexChanged` is raised | [View manager](../../../src/FerroUI.Controls.Repeater/view_manager.rs); no element is recreated for a move |
| WR-35 | When the focused element is cleared, WinUI focuses the element at the next or previous index (`ViewManager::EnsureFocusedElement`) with the previous `FocusState` | The search covers every realized row held by the layout, nearest first, takes the last focusable descendant of an earlier row and the first of a later one, and clears focus when no candidate takes it; a keyboard focus (`:focus-visible`) is carried to the replacement as a Tab focus | [View manager](../../../src/FerroUI.Controls.Repeater/view_manager.rs) (`move_focus_from_cleared_index`); a keyboard user who deletes the focused row keeps a visible focus |
| WR-36 | `ViewportManager` tolerates a viewport shift of up to 1 pixel before it measures again (`ViewportManager.cpp`) | Any nonzero pending shift measures again | [Viewport manager](../../../src/FerroUI.Controls.Repeater/viewport_manager.rs); exact offsets at the cost of an extra measure for sub-pixel shifts |
| WR-37 | The `SelectedItems` vector view rejects `IndexOf` | As an `ItemsSource` the view answers `IndexOf` with a linear search, and a read at a stale index has no item | [Selected items](../../../src/FerroUI.Controls.Repeater/selection/selected_items_markup.rs); a selecting control bound to it (SelectedItem, ScrollIntoView) does not fail |

The plain Rust `Result`/programmer-error split follows the existing
[porting guide](../PORTING-GUIDE.md). Native factory and metadata errors retain
typed error information. Invalid layout-context usage, impossible ownership
transitions and forbidden reentrancy are programmer errors. A Rust `panic!`
used for such a precondition is not an implementation placeholder.
