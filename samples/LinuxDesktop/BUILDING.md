# Build and run Ferro Desktop

Use a native Linux Rust toolchain (the workspace declares Rust 1.89 or later), a C++17 compiler, pkg-config, fontconfig development files, and the development dependencies for FerroUI’s X11, Wayland (including libwayland-client and libwayland-egl) and Skia backends. The compositor seat uses libxkbcommon (on Debian/Ubuntu install `libxkbcommon-dev` and `xkb-data`). The header fetch uses Bash, curl, GNU tar, sha256sum and flock. Running the accelerated session requires a Vulkan loader and a Vulkan 1.1 driver that can present to the current Wayland or X11 display.

From the repository root, build a release binary or start the shell inside your current desktop.

```sh
samples/LinuxDesktop/build.sh
samples/LinuxDesktop/build.sh run
```

The wrapper selects the Linux Graphite and Vulkan build of Skia for the desktop's dependency graph. It verifies the source-header archive for the locked rust-skia release and caches the required Skia, Vulkan and skcms headers under `$XDG_CACHE_HOME/ferroui/skia` (default `~/.cache/ferroui/skia`). Builds sharing a cache can start concurrently. To use an existing matching checkout without fetching the header archive, set `FERROUI_SKIA_HEADERS` to the source root for rust-skia/skia tag `m153-0.101.2`. The checkout must contain `include/` and `modules/skcms/`. For a fully offline build, Cargo dependencies and the corresponding native rust-skia binary must also be cached.

```sh
FERROUI_SKIA_HEADERS=/opt/skia-m153-0.101.2 samples/LinuxDesktop/build.sh check --offline
samples/LinuxDesktop/build.sh build --profile dev
samples/LinuxDesktop/build.sh test
```

## Run as a login session

The same installer provides **Ferro Desktop (Wayland)** and **Ferro Desktop (X11)**. The Wayland session starts Sway, which owns input, outputs, compositing and application windows. FerroUI renders its own panels, wallpaper and overlays. See [Wayland session setup, portals and tests](WAYLAND.md).

### X11 session

Install Openbox 3.6 or later, Bash, D-Bus, and your distribution's Xorg display-manager support. Install the binary produced by the release build, then select **Ferro Desktop (X11)** in the login screen.

```sh
sudo samples/LinuxDesktop/session/install.sh target/release/ferro-desktop
```

The installer writes the binary and supervisor to `$PREFIX/bin` (default `/usr/local/bin`), the Openbox configuration to `$PREFIX/share/ferro-desktop`, and the login entry to `$XSESSIONS_DIR` (default `/usr/share/xsessions`). The display manager must have `$PREFIX/bin` in its executable search path. Use `DESTDIR` to stage all files for packaging. Set `$XDG_CONFIG_HOME/ferro-desktop/openbox.xml` to customize the window-manager bindings.

| Action | Login-session shortcut |
| --- | --- |
| Reveal the desktop and open the launcher, or return to the applications | Super+Space or Super+D |
| Switch to a workspace | Super+1 through Super+4 |
| Move the focused window to a workspace | Super+Shift+1 through Super+Shift+4 |
| Cycle windows | Alt+Tab or Alt+Shift+Tab |
| Toggle maximize / minimize the focused window | Super+Up / Super+Down |
| Close the focused window | Alt+F4 |
| End the session with confirmation | Ctrl+Alt+Delete |

## Test the session adapter

The native tests start a private X server and D-Bus session, run the shipped login supervisor, and create an independent X11 client. They verify title changes, focus, minimization, workspace moves, close negotiation and window removal. The decoration test keeps the same client mapped and checks Openbox's published theme and actual frame extents through the three appearances. These tests require Xvfb, xauth, Openbox and dbus-run-session.

```sh
samples/LinuxDesktop/tests/session.sh test
```

In a managed login session, Openbox updates title bars, buttons, borders and menus for existing server-decorated X11 clients. Windows places system buttons on the right, macOS places compact circular controls on the left, and Material gives the title bar more height. Colors come from the shell appearance descriptor. The supervisor copies the selected Openbox settings to a private runtime directory, retaining window rules, shortcuts and fonts. Applications that draw their own title bars and content control those pixels themselves.

To reproduce the managed-session screenshots, the capture mode opens an ImageMagick viewer on the Julia-set fixture generated by `tests/julia.py`. It uses xdotool to drive the production appearance picker and captures the root window. This additionally requires Python 3, xdotool and ImageMagick 6.

```sh
samples/LinuxDesktop/tests/session.sh capture target/release/ferro-desktop /tmp/ferro-frames
```

## Measure launcher latency and idle CPU

The launcher benchmark starts its own Xvfb display, Openbox session and fixed application catalog. It warms the Start panel, injects keyboard input with XTest and polls a window pixel with XGetImage. The JSON output includes individual open and close latencies, their medians, the process CPU tick count and the measured idle interval.

```sh
python3 samples/LinuxDesktop/tests/benchmark-launcher.py target/release/ferro-desktop
```

For comparisons, use the same compiler profile, Vulkan driver, display resolution and system load. The probe measures input to the first changed X11 window pixel. Physical display scanout and client application startup are separate measurements.


## Exercise desktop services

The native suites create private X displays, settings directories and D-Bus sessions. The device-controls suite also starts an isolated PulseAudio daemon with a null sink and exports NetworkManager and UPower test objects. It verifies the sink volume, mute state and radio writes through the same interfaces used by the shell. Physical backlight access depends on the active logind session and hardware.

```sh
samples/LinuxDesktop/tests/favorites.sh target/release/ferro-desktop /tmp/ferro-favorites
samples/LinuxDesktop/tests/notifications.sh target/release/ferro-desktop /tmp/ferro-notifications
samples/LinuxDesktop/tests/system-controls.sh target/release/ferro-desktop /tmp/ferro-system
samples/LinuxDesktop/tests/shortcuts.sh target/release/ferro-desktop /tmp/ferro-shortcuts
```

For the search benchmark, use `samples/LinuxDesktop/build.sh test benchmark_catalog_search -- --ignored --nocapture`. For the X11 window-title benchmark, run `samples/LinuxDesktop/tests/session.sh benchmark`.
