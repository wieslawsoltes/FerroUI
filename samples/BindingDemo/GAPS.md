# BindingDemo: gaps

What the port of the sample found in the framework. Every gap has a reproduction in `tests/gaps.rs`, or in the test of the shell that is named with it; a gap that is fixed keeps its test, which then asserts what the framework does now.

```sh
cargo test -p binding-demo --lib
```

Status: 3 documents (`App.xaml`, `MainWindow.xaml`, `TestItemView.xaml`), all converted without an edit, all compiled by the build, all load with the run-time loader too and show their class; 5 tabs, all selected, laid out and rendered through the compositor with Skia by `tests/shell.rs`.

## Bindings that report an error

`tests/shell.rs` (`the_bindings_of_the_window_report_the_accepted_errors`) visits every tab and compares the errors the bindings report with two lists; the desktop host prints the same two reports when it starts.

- `ACCEPTED`, a report the managed original makes too: `Button.Command <- NestedModel.Command at NestedModel: Value is null.` (`Command="{Binding NestedModel.Command}"`: `MainWindowViewModel.NestedModel` is null until one of the commands of the tab ran, and a null in the middle of a path is an error of a binding).
- `GAPS`, the report of the open gap B002, which the managed original does not make in this form: the reflection binding of the content control.

## Differences of the port that are not gaps

- **The background thread** (was B004). `Task.Run(() => { while (true) { CurrentTime = DateTimeOffset.Now.ToString(); Thread.Sleep(1000); } })` sets the property on the thread of the task, and the binding takes the change over to the thread of its target. A view model of the port is an object of the thread that created it (`Rc`, not `Send`): the background thread reads the clock, formats the time and posts the text (a `String`) to the dispatcher of the view model, where a function finds the view model by a number in a table of that thread and sets the property (`ViewModels/main_window_view_model.rs`, `CurrentTimeThread`). Nothing of the object model crosses the thread, and there is no `unsafe` and no wrapper that makes an `Rc` sendable. The thread ends when the view model is dropped; the one of the managed original runs until the process exits.
- **The timer of the reactive library** (was B005). `Observable.Timer(TimeSpan.Zero, TimeSpan.FromSeconds(1)).Select(x => DateTimeOffset.Now)` is a package the managed sample references; the observables of the framework have no timer. The sample has the operator as a local function over dispatcher timers (`timer`): the values are produced on the thread of the view model, where the operator produces them on a thread of the thread pool. The property is declared to markup as the untyped observable of the stream operator (`ObservableValue`), so the compiler sees `IObservable<object>` where the managed original has `IObservable<DateTimeOffset>`; the text box shows the same text.
- **Generic types in markup** (was B006). The documents name instantiations of three generic types (`{x:Type vm:MainWindowViewModel+TestItem, x:TypeArguments=x:String}` as a data type and as the data type of a binding with a source, `{local:GenericMarkupExtension Value=Red, x:TypeArguments=Color}`, `<local:GenericValueConverter x:Key="BrushConverter" x:TypeArguments="SolidColorBrush"/>`). Markup knows the instantiations a crate declares metadata for, not the open type (`docs/porting/DEVIATIONS.md`, "Run-time type system of markup"): the three classes are generic in the port too, and each declares the one instantiation the documents name through a carrier type (`TestItemOfString` under the name of the nested class, ``MainWindowViewModel+TestItem`1``; `GenericMarkupExtensionOfColor`; `GenericValueConverterOfSolidColorBrush`). Another type argument in a document is an error of the build. All of it compiles and runs: `tests/shell.rs`, the basic tab (the shared item), the list box tab (the data template) and the advanced tab ("Color: Red", "SolidColorBrush: Yellow").
- **The method command** (was B007). `Command="{Binding Do}"` with the private `[DependsOn(nameof(BooleanFlag))] bool CanDo(object parameter)`: both methods and the attribute are declared in the markup metadata of the view model, and the button follows the flag (`tests/shell.rs`, the commands tab).
- **`GetErrors` of `IndeiErrorViewModel`** returns an array of one element that is null while there is no error; the contract of the port has no null error, and the method returns no element then.
- **`MainWindow.xaml` needs the constructor**: the document refers to a resource the constructor sets before it loads the document (`Resources["SharedItem"] = ..`). The tests that load the document on its own populate an instance with that resource (`MainWindow::before_document`, through the `uninitialized:` part of `xaml_class!`).
- Subscriptions of a view model to its own properties hold it weakly where the managed original captures `this`: a cycle a collector frees, and here a leak.

## What the tests do not reach

- The data template of the content control of the list box tab (`TestItemView` for the selected item) is never built by the window while B002 is open; the class and its document are covered by the generated tests of the document.
- The validation by data annotations of the builder of the upstream entry point and the developer tools of a debug build have no counterpart (`program.rs`).
