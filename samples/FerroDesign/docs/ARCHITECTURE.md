# Architecture

## Runtime boundaries

`ferrodesign-core` is a UI-independent Rust library. It owns document semantics and can be tested or used by another client without initializing FerroUI. `ferrodesign-app` supplies the native control tree, gesture handling, property editors and rendering. Browser and native entry points configure platform services, then construct the same application.

`Editor.xaml` is compiled by the `ferroui-build` build task and loaded through a `ferres://FerroDesign/ui/Editor.xaml` resource URI. The shell uses actual FerroUI `Grid`, `StackPanel`, `ScrollViewer`, `Button`, `TextBox`, `ComboBox`, `Border` and related controls. The application registers the Inter font and the FerroUI Fluent theme. Control events and the document state are wired with FerroUI `Ref<T>` handles and weak `Rc` controller references.

The custom `DesignCanvas` extends FerroUI `Control` with `ferro_class!` and implements the normal rendering and input contracts. It handles routed pointer/key events, pointer capture, focus, clipping and visual invalidation. No HTML element substitutes for a design layer or a property editor. Browser JavaScript is limited to the runtime bridge and host capabilities.

## Rendering through FerroUI

`ScenePainter` accepts a `DrawingContext`, a `Document`, the root node IDs and a document-space viewport. It knows no Vello, Skia, OpenGL, WebGPU or platform framebuffer types. Its primitives include:

| Document feature | Public FerroUI API |
| --- | --- |
| Paths, polygons, curves and ellipses | `StreamGeometry`, `IGeometryContext`, `EllipseGeometry`, `RectangleGeometry`, `GeometryGroup` |
| Boolean combinations | `CombinedGeometry` and `GeometryCombineMode` |
| Solid and gradient fills | Immutable solid, linear-gradient, radial-gradient and `ImmutableConicGradientBrush` brushes |
| Raster image fills | `Bitmap`, `ImmutableImageBrush`, normalized source rectangles and stretch/alignment/tile modes |
| Strokes | `ImmutablePen`, dash style, line caps/joins and widened geometry for alignment |
| Text and rich text runs | Cached `TextLayout`, run properties and `TextLayout::build_geometry` for positioned glyph/decoration contours |
| Editable outlines | `Geometry::try_get_path_data` and complete `TextLayout::try_build_geometry` capabilities |
| Nested geometry | `push_transform`, clip and isolated `try_push_compositing_layer` scopes |
| Shadows and layer blur | `BoxShadow`, `BoxShadows`, geometry and `ImmutableBlurEffect` |
| Background blur | Bounded `RenderTargetBitmap` prefix/source/filter surfaces, geometry clips and premultiplied compositing |
| PNG export | `RenderTargetBitmap` and the FerroUI bitmap encoder |

The browser app disables FerroUI.Browser's default features, enables only `vello`, and selects `BrowserRenderer::Vello`. The build checks the resolved target graph for Vello and rejects any active `ferroui-skia`, `skia-safe` or `skia-bindings` dependency. Optional packages in `Cargo.lock` are not linked merely because they appear there. The framework's independent backend implementations remain available to other applications.

The default browser mode list is WebGL2 then Software2D: FerroUI Vello uses its hybrid renderer on the registered WebGL2 context or CPU rasterization to the platform framebuffer. An explicit `RenderingMode` selects exactly Software2D or WebGL2; WebGL1 is rejected before application startup. Native launchers use `VelloApplicationExtensions` with hybrid/Metal on macOS and the platform OpenGL contexts (GLX on Linux/X11, WGL on Windows). All retain CPU framebuffer fallback, and `--software` requests it directly. HarfBuzz shaping and embedded Inter fonts are shared with the XAML control tree. The headless smoke command uses Vello through FerroUI's render-target and bitmap APIs. Source-tagged validation distinguishes the earlier baseline from later editor changes; backend configuration alone does not establish a passing run.

### Angular paint contract and interchange

`Paint::AngularGradient` stores a relative center, clockwise angle in degrees and ordered RGBA stops in the portable core model. Zero degrees points up. Validation rejects nonfinite geometry, empty stop arrays and invalid offsets. Scene preparation and native paint previews create the public `ImmutableConicGradientBrush`, sorting a copied stop list and normalizing its angle without rewriting authored data. Relative coordinates refer to the brush's actual draw target, including the public stroke/text rendering contract. The visual fingerprint includes center, angle and every stop, so edited paints follow ordinary scoped invalidation and unchanged camera frames reuse their immutable brush. Compatible Smart Animate tracks interpolate centers and stops while crossing the angle seam by the shortest path.

JSON retains the editable paint; PNG uses the common FerroUI renderer. XAML emits native `ConicGradientBrush` property elements with ARGB stops and paint opacity within the existing exporter subset. SVG has no portable conic primitive, so `svg.rs` emits at most 1,024 vector sectors and reports the approximation in metadata, export warnings and the native toast. Separate user-space tile and brush-reference bounds cover stroke extents without repeating at the unstroked edge; complex aligned outlines, arrowheads and shaped text can still have different native paint bounds. CSS samples the native straight-RGBA ramp where both color and alpha vary, preserves authored hard stops and caps additional samples at 1,024. Its source comment discloses the approximation, and a one-stop brush becomes a constant color. Neither export is an exact angular interchange contract. See [angular paints](ANGULAR_PAINTS.md) for the sampling budgets and authoring limits.

## Retained scene and invalidation

The document has stable node IDs and parent-relative affine geometry. The editor updates a scene index after a document change. Scoped paint/text property updates can preserve the spatial index; geometric changes update the affected subtree; hierarchy, visibility or stacking changes rebuild traversal where required. Native inline text editing retains full layout and refresh. Tests compare incremental results to a full rebuild, including clipped transformed descendants and root-level reorder.

The renderer caches immutable geometries, brushes, pens, shaped text and image assets. A prepared traversal stores subtree bounds and skip ranges. Camera-only changes reuse the prepared scene; offscreen subtrees can be skipped without rebuilding path or text data. Normal canvas painting and PNG export use `render_editor` and `rendered_editor_bounds`. An opaque editor token identifies a bounded, complete change feed: 128 entries, 16,384 retained IDs and a 4,096-ID query/dependency limit. Scoped changes refresh transforms and inherited outline requirements in preorder, then visual fingerprints, derived geometry and ancestor bounds in postorder. Full and incremental preparation share the same visual-building function.

Prepared scenes with at least 32 roots also build `RootPaintIndex`, a balanced bounding-volume hierarchy in `renderer/root_index.rs`. Each leaf refers to a prepared root and its conservative world subtree bounds/node count, including overflow and effect extents. Median partitioning follows spatial centers and uses original root slots to break ties. A viewport query rejects whole branches, then sorts surviving prepared indices back into document paint order before `paint_subtree`. The complete root order remains available for backdrop-prefix sampling. Spatial partitioning never changes alpha/blend stacking order.

The index retains its candidate allocation and last viewport. An unchanged viewport reuses the candidates with no new bounds tests; a changed prepared-root bound refits its leaf and ancestors and invalidates that query. Structural preparation rebuilds the index. When the viewport contains the full root bounds, painting reuses the retained ordered root list without traversing the tree or sorting it. Fewer than 32 roots use direct traversal. Nonfinite derived bounds remain conservatively unbounded, so they cannot incorrectly prune otherwise valid descendants. Broad-phase counters are `rootBoundsTests`, `rootCandidates` and `rootQueryReused`; subtree culling still runs within each candidate root.

Structural/generic transactions, editor identity changes, expired history, oversized dependencies, changed roots/assets and unsupported incremental conditions request full preparation. Direct `Document` rendering and disposable prototype scenes keep the conservative preparation path; arbitrary public document writes require `Editor::refresh()` or painter invalidation under the existing mutation contract. Lifetime counters retain full/incremental preparations, prepared nodes and rebuilt visuals across cached frames and bounds queries. These counters measure preparation work, not GPU time: root signatures still hash root IDs, visible descendants still require drawing, and direct sibling aggregation can still be linear. Overlapping root bounds can also require a broad query and a large candidate sort. Missing images and declined effects appear in render diagnostics. Cropped image brushes and SVG export share a normalized source window. Lightweight embedded-image header inspection obtains source dimensions without decoding or copying the full image during a crop gesture.

`DrawingContext::try_push_compositing_layer` is a public optional capability carried through platform contexts, recorded render data, drawing groups and proxy/replay paths. Skia and Vello implement the requested blend mode and one opacity value for the completed layer; unsupported contexts decline without changing state. Containers isolate their children, which prevents individual overlapping children from receiving group opacity more than once.

Shadow order is consistent across FerroUI's rounded-rectangle `BoxShadows` path and the cached general-path shadow path. The model lists the highest shadow of each kind first; cache preparation reverses box-shadow submission, and general-path drawing traverses shadows in reverse. Drop shadows paint before the body. Leaf shapes and derived Boolean shapes paint fills, inner shadows and then strokes, preserving opaque stroke coverage. Containers paint their own body and clipped descendants before their inner shadows. Layer/background blur retain their existing scopes around these paint phases; the effect array is not a generic arbitrary filter graph.

Background blur samples the painted prefix of the nearest isolated parent. A padded offscreen prefix and source are composed with the blurred prefix inside the node geometry, then interpolated in premultiplied space for node opacity. Source replacement prevents translucent pixels from being added over a second copy of themselves. A document isolation excludes host decorations, while active ancestor clipping/effects/opacity remain outside the replacement and apply once. Cache entries are bounded and keyed by prepared scene and sampling scale; camera pan reuses them. The host supplies zoom times display scaling, and PNG export supplies its own output scale. Allocation/depth limits are explicit diagnostics.

`DesignCanvas` owns the camera. World/screen conversion and zoom anchoring live in the core `Viewport` type. The canvas adds selection bounds, resize/rotate handles, hover outlines, alignment guides, frame labels, rulers and local comment pins after the artwork pass.

The layer sidebar is an ItemsControl with a VirtualizingStackPanel and a flattened hierarchy of lightweight row values. Native control containers are realized for the viewport. A shell-owned projection cache consumes the editor's bounded change feed and checks displayed metadata only for represented dirty nodes and ancestors. Scoped geometry edits can therefore reuse the row vector, names and native item source. Full or missing history, editor replacement, hierarchy changes, page/assets context changes and nonempty search retain a complete projection; changed row metadata replaces the item source. An expanded-set snapshot is compared on reuse and cloned only after a full projection, so expanding or collapsing cannot bypass invalidation. That equality check can still visit expanded IDs. The shell releases model/cache borrows before native collection setters and keeps weak row references so scrolling can release offscreen controls. Lifetime projection build/reuse counters are separate from scene-preparation counters.

The benchmark in `ferrodesign-core/examples/performance.rs` measures document creation, indexing, hit tests, viewport queries, drag refresh and undo/redo for a synthetic grid. It does not measure the canvas renderer, the layout of the sidebar control tree, GPU time or display frame rate.

## Editing and history

An `Editor` owns a document, the active page, selection, clipboard, spatial scene and history. Ordinary live-edit pointer gestures start one transaction, apply intermediate updates, then commit one undo entry. Escape cancels that transaction and restores its initial state. Nested editing helpers participate in the active transaction rather than adding one history item per pointer event. Auto-layout reordering uses a separate deferred preview described below: it starts no document transaction until the drop has been validated.

History records changed nodes and document metadata. Scoped node transactions snapshot their known mutation set and maintain incremental scene state; one gesture keeps the original scoped snapshot until commit/cancel. Pointer gestures retain a full snapshot when the document contains any auto-layout node, because layout can affect ancestors and siblings. Generic and structural operations retain a full transaction and can promote an active scoped transaction when necessary. Undo/redo move complete history payloads while restoring exact node state. Grouping, reparenting and ungrouping preserve world geometry; duplication remaps internal node, component-property and prototype references. World movement is converted through the parent inverse transform so that children of rotated containers move correctly.

Constraint resizing updates children relative to the old and new container extent. Auto layout implements row, column, wrapping, fixed/fill/hug sizing, padding, spacing, alignment, min/max limits, absolute children and grid placement. Optional grid metadata specifies row, column and positive spans; native fields translate one-based coordinates to zero-based storage. Explicit cells reserve occupancy before deterministic automatic placement, excluding hidden and absolute children. Connected groups of overlapping row spans share a stable equal-height track policy so allocated Fill sizes cannot repeatedly enlarge a Hug container. Grids without nondefault placement preserve the existing fast path.

Native placement/sizing and before/after reorder operations stage and validate a candidate document before a full history transaction, because arranging one child may move siblings and resize ancestors. Reversed flow translates visual order back to stored child order; pinned cells preserve coordinates. Rejected drafts and repeated no-op operations retain document/history state. Common container controls remain in the inspector, with the native child-layout dialog supplying placement, spans, limits, growth and relative order.

### Deferred auto-layout drag

The core `LayoutDragSession` retains the selected child's ID, the parent/children/layout/revision, compact sibling geometry and world transforms. Construction reads siblings once and builds a balanced spatial tree over their actual world insertion edges. It retains no paint, image, text or vector payload copies. Pointer-frequency target queries allocate nothing and do not run auto layout; the nearest insertion edge supplies a visual-flow index and a world-space line. Typical spatial queries prune most branches; overlapping insertion geometry can require more work. The original child layout rectangle defines an explicit no-op region.

`canvas/layout_drag.rs` owns pointer capture and a four-screen-pixel activation threshold. `DesignCanvas` draws a translated outline, a constant-screen-width insertion line and end caps through public `DrawingContext` operations. This adorner state is separate from nodes, the editor revision, undo/redo and autosave. It is exposed by the read-only `layoutDrag` diagnostic probe. The renderer's prepared artwork remains reusable while the overlay changes.

On release, the canvas takes the retained gesture before releasing capture or raising shell callbacks. It checks document/editor revision, single-child selection and transaction ownership; `Editor::commit_layout_drag` additionally checks the original parent, sibling geometry, transforms and layout. Only a valid changed target stages a candidate document and commits its reorder/reflow as one transaction. Invalid or stale sessions leave history intact. Returning to the original slot or canceling for Escape, capture loss, tool/camera changes discards the session without a restoration write. An Undo command during the preview first cancels the owned interaction, preserving the previous committed history item for the next Undo. Late pointer events cannot reuse the discarded session.

This indexed single-child path is complemented by `layout_transfer.rs` for multiple selected roots and cross-parent drops. A transfer session normalizes selected roots, retains their visual order and carries opaque editor/transaction ownership. It previews a layout insertion or free-parent destination without changing the document. Release stages one candidate that preserves world transforms in the destination coordinate system, validates hierarchy/layout and commits once. Entering automatic layout clears placement pins only on transferred roots; unselected hidden, absolute and pinned siblings retain their metadata. Empty layout frames, ordinary frames and the active page are destinations. A stale editor, selection, revision or transaction cannot commit or cancel another gesture's work.

Both paths use arranged row, column, wrap or grid geometry, including reversed flow and affine parents. Hidden/locked ancestry, locked sources and materialized instance descendants are excluded. Returning to the initial placement, Escape and lost capture discard the preview. Pointer-based arbitrary empty-cell pinning remains in the native placement dialog.

### Local style definitions

`style_edit.rs` validates fill, typography and effect definitions before updating the live document. Creation/application, definition replacement, rename, detach and delete are explicit editor transactions. Definition edits traverse linked nodes across pages, preserve character overrides and update hidden/locked linked layers. Direct layer edits detach only changed bound properties. The common update paths borrow the already-captured prior node to compare style fields, avoiding another image/paint/effect payload copy on ordinary moves; an explicitly unrefreshed legacy document mutation uses a conservative snapshot fallback.

Nodes retain effective values alongside style IDs. This supports independent portable rendering, appearance-preserving detach/delete and safe handling of old documents with customized stale bindings. The native `shell/styles.rs` controls edit complete supported stacks and typography through this API. They share the shell's draft registry, IME ownership, validation and lifecycle-save boundary. Bulk definition propagation remains a document-sized operation; the optimized comparison path does not make shared updates constant-time.

Angular paint fields in `shell/paints.rs` and `shell/styles.rs` use these existing edit boundaries for center, angle, stop colors/positions and opacity. Type conversion reads the current confirmed paint and carries every gradient stop into the new gradient kind. Re-selecting the same kind leaves its geometry unchanged. Manual layer edits detach the corresponding fill-style binding; definition edits propagate the supported angular data through the ordinary shared-style path.

### Conservative vector face discovery

The UI-independent `vector_faces.rs` operates on the authoritative `VectorNetwork`. `detect_faces` returns bounded regions as oriented references to original edges; `face_at` queries an individual region in node-local coordinates. A normalized control-hull sweep and Bézier subdivision certify the embedding without replacing authored curves with sampled polylines. Iterative bridge discovery excludes dangling branches from the face walk while leaving those edges in the document. Tangent-ordered directed edges define face traversal, integrated Bézier area determines orientation, and polynomial winding assigns nested holes to their containing face. Both nonzero and even-odd regions keep their original edge and control-point data.

The compiled XAML **Fill all closed regions** button calls `DesignCanvas::network_fill_faces` and then `Editor::fill_network_faces`. Geometry checks and ID reservations finish on a candidate before the existing scoped update commits. Matching regions retain their IDs and serialized contour order; newly discovered faces use the existing monotonic allocator. The operation preserves layer identity, bounds, transforms and stroke ownership, adding one neutral fill when faces exist and the layer has no fill stack. Repeated unchanged calls and preflight failures leave selection, revision, history and redo intact. All discovered regions continue to share the layer's paints.

This action requires intersections to be represented by shared vertices. It declines unsplit crossings, ambiguous contacts, coincident outgoing tangents and unresolved orientation rather than constructing intersection topology. Discovery has a 32,768-edge limit, a one-million-unit geometry work budget and subdivision depth 40; overlapping control hulls can still require substantial work before a limit is reached. It runs only for an explicit authoring command or core API query, never as part of ordinary frame preparation or pointer movement. A dedicated paint-bucket tool and separate region paints are not supplied by the read-only face query. See [vector face discovery](VECTOR_FACES.md) for the detailed contracts.

### Editable geometry conversion

The UI-independent `flatten.rs` creates and validates a conservative conversion plan before beginning history. It checks hierarchy, appearance, masks, component ownership and references to descendants that would be removed. The application supplies the geometry through `renderer/flatten.rs`, reusing the same prepared FerroUI geometry as scene painting. Public `GeometryPathData` preserves independent optional fill/stroke paths, fill rules and original curve segments. The application performs no backend downcast or curve sampling.

`TextLayout::build_geometry` is a reusable public outline path for rendering effects. Its optional complete sibling, `try_build_geometry`, propagates capability failure for any run without complete monochrome outlines; the legacy API retains its partial-outline contract. Vello includes the same shaped glyph offsets as normal glyph rendering and conservatively declines color/bitmap/SVG-font conversion. Flatten checks every prepared text descendant, so a partially outlined mixed run cannot silently lose a glyph. Supported conversion preserves the surviving layer identity and its parent-relative coordinates; unsupported cases leave revision, allocation, selection and undo/redo untouched.

### Typed effect authoring

`effects_edit.rs` provides `EffectPropertyEdit`, `EffectStackEdit` and `Editor::edit_effects` independently of FerroUI. A batch deduplicates selected IDs, skips effective locks, clones only candidate effect stacks and validates every changed stack before touching live state. Properties address matching stack indices; missing rows are unchanged. Add/insert/duplicate/remove/move/replace/clear share the same path. Invalid batches and no-ops preserve selection, revision, redo and style bindings. Accepted changes use known-node history and the existing node/ancestor change feed because effects do not affect auto-layout sizing. Changed nodes detach their effect style and mark an explicit `effects` override.

The native `shell/effects.rs` editor builds real ComboBox, TextBox, CheckBox, Button and swatch controls inside the compiled XAML modal host. It shows the first unlocked selected layer while applying matching edits across the selection. Fields commit on Enter or focus loss, restore the last committed text on Escape, and step numbers with Up/Down (1), Shift (10) and Alt (0.1). A tunnel handler gives these field shortcuts priority over the TextBox caret handler, while active composition remains owned by the native IME. RGB changes preserve each layer's alpha; percent opacity is quantized once to 8-bit alpha. Radius and signed distance limits reject nonfinite or out-of-range values before mutation.

Reordering, removing or changing an effect type rebuilds native rows. An update guard suppresses LostFocus commits from discarded controls, and a captured-selection check rejects stale callbacks after selection changes. Common edits retain controls and update the real renderer; dedicated stack actions still produce one history boundary each. The native color fields and numeric controls replace the previous effects JSON editor; structured layer data remains available for other properties.

Interactive vector editing uses stable path-command/point identifiers within a gesture. Curve splitting preserves cubic and quadratic shape; nearest-point queries isolate polynomial stationary points instead of using display tessellation. Persistent tangent modes constrain later handle edits. Bend uses a picked curve parameter; erase removes the chosen edge without silently reconnecting its neighbors. Vector networks have stable vertex, edge and oriented-region IDs, separate fill/stroke paths and explicit topology validation. Recomputing tight bounds compensates the node transform, including the center-of-rotation change and reflected/sheared parents. Constraint and auto-layout resizing also scale vector geometry while preserving graph identities.

The on-canvas text editor is a FerroUI TextBox transformed into the selected layer coordinate system. The scene temporarily omits that text layer without changing its authored visibility. Confirmed synchronous text-changing events update the open transaction, and focus loss/Ctrl+Enter commits it; Escape cancels it. A minimal Unicode character diff remaps rich-run UTF-8 byte ranges. The native control owns caret navigation, selection, IME and text clipboard handling. A separate native character-style dialog converts native selection indices to validated UTF-8 boundaries, splits/coalesces style runs, and previews `Run` values through FerroUI inline text controls.

`TextBox::is_composing_text()` reads pending preedit from its native input client. The client publishes that state before changing the presenter, and clears it when the input method explicitly ends preedit or the presenter detaches. Unlike visual preedit, the state survives selection deletion and caret synchronization. The shell excludes text-changing notifications while preedit is pending, retaining confirmed text and rich runs for autosave and lifecycle commits. Browser composition cancellation also resets the shared hidden-input bridge, so delayed events cannot write into a replacement text client. Input-only Unicode insertion is forwarded through the native text event and resynchronized after native caret handling.

## Prototypes and local services

The core prototype player is a deterministic state machine for navigation history, modal overlays, session variable overrides and external requests. Pointer events and normalized key chords dispatch through the active root; after-delay rules use native FerroUI DispatcherTimer subscriptions. Activation tokens prevent stale timers from firing after navigation or overlay closure, and unrelated overlay changes do not rearm an existing timer. Long delays are split into cancellable chunks; zero delays yield a UI turn.

The runtime snapshots the authored document, selection, active page, camera and tool. Presentation works on a disposable document and restores the snapshot on exit. Serialization during presentation reads the authored snapshot, so variable bindings cannot autosave preview values into the design. A native timer samples deterministic transitions and matched-layer Smart Animate; incompatible artwork crossfades. Activation-scoped hover/press sessions restore their prior state after release/exit even when navigation temporarily changes materialized IDs. Scroll offsets clamp against container content and refresh changed preview nodes; they do not become authored positions or camera substitutes. External links are validated before the platform opener is invoked.

Component reconciliation stages only relevant materialized subtrees, preserves stable IDs and explicit overrides, and supports named variants plus typed text/boolean/instance-swap properties. Native controls hold compact identity/name metadata instead of copies of image/vector nodes. Reconciliation can propagate into dependent instances and layout, so its Editor wrapper still takes a full history snapshot. Variable authoring likewise validates typed values, aliases, modes and bindings atomically; legacy imported variable definitions remain available with diagnostics.

All persistence is local. JSON is validated before replacing a document. A 220 ms native dispatcher debounce coalesces edits before complete, compact JSON serialization, while a pending-snapshot signal keeps lifecycle guards active. `PrototypeRuntime::autosave_json()` selects the authored snapshot during presentation and the current document otherwise, releasing its borrow before the storage bridge. Portable exports use the existing pretty serializer. The first compact save of a previously pretty snapshot can add one format-only storage revision because deduplication compares strings. The browser host then uses a coalescing IndexedDB save queue and downloads portable files. Current/previous records commit atomically, failure status remains visible, and revision comparisons prevent a stale tab from overwriting another tab. Status notifications are posted asynchronously to avoid JavaScript-to-Rust reentry while a shell callback is active. Visibility/page lifecycle events commit native drafts and flush pending serialization before storage; unsaved changes use a before-unload indication. Rejected snapshots remain pending and are not reported as saved. Native saves use a temporary file and atomic replacement, with a closing hook that flushes the pending edit. Comments, components, variables and history are local concepts; no authentication, collaboration transport or hosted sharing service is implied by their presence in the UI.

## Extending the editor

Add document semantics to the core with a focused test for the invariant being changed. Add a command to the shell and bind it through the XAML controls or quick actions. Keep scene drawing in `ScenePainter` and use public FerroUI media types so that browser, desktop and PNG export retain a common rendering path. Keep host-only operations in `platform.rs`; browser DOM should not acquire a second editor implementation.
